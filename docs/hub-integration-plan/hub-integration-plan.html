Executive summary

The Hubs, analytics backend, and perturbation tooling all exist, and CTSM runs to completion in the container. Finishing the work is a data-rebind and validation effort, not a redesign: every Hub reads from a hardcoded UW-Madison S3 store and must be repointed at the live/native data flow, then validated against reference outputs.

Now unblocked. The July 9 comment thread on communication-internal.docx settled the open design questions: move to live/native data, the Experimentation Hub loop is confirmed, and the Kalman filter target is set.

Deliverable

A self-contained local Docker image, single-user, no auth, in which all three Hubs run end-to-end against live NEON input and in-container CESM output, validated on the five sample sites.

Out of scope (follow-on): VM hosting, multi-user, authentication, and S3 credential-rotation security work.

Why the rebind is low-risk

The S3 and live-run layouts share one filename convention, so repointing changes where the code looks, not how it parses:

S3 today : archive_1/{site}.transient/lnd/hist/{site}.transient.clm2.h1.{YYYY-MM}*.nc
Live run : {output_root}/{site}.transient/lnd/hist/{site}.transient.clm2.h1.{YYYY-MM}*.nc

The soil-profile plotting function already has a local-path branch. The core change is flipping the default source and generalizing the two S3-only readers.

Roadmap

PHASE 0

Data contract + fixtures

~0.5 day

Run KONZ to completion; document the live output path, filename convention, variables, and units; stage the five Drive reference copies into the repo as the validation oracle.

Done when: a reviewer can locate a live history file from the documented path without guessing.

PHASE 1

Rebind the data-access layer

~1 day

The one real refactor. Add a local reader, route it through a single source-agnostic entry point (env-var selected, local default, S3 opt-in), and remove the hardcoded S3 path. S3 functions stay available.

Done when: data loads from a live run with no S3 credentials present; the S3 path still works when explicitly selected.

PHASE 2

Hub 1 — Data Analysis

~0.5 day

Simplest Hub first. Swap the notebook's S3 calls for the new entry point, drop the mandatory credential preflight, re-run against live output.

Done when: plots and histograms render from live output and match the KONZ reference within tolerance.

PHASE 3

Hub 2 — Modeling / Kalman filter

~1 day

Point the misfit and calibration workflow at native output, confirm the filter targets GPP, validate bias / residual / R² and the calibrated result against the reference notebook.

Done when: misfit and calibration numbers reproduce the reference results within tolerance on at least two sites.

PHASE 4

Hub 3 — Experimentation

~1.5 days

Wire the confirmed 4-step loop: one NEON input → one perturbed copy (precipitation first — fully codified) → run CESM on both → t-test the outputs. Confirm the in-scope perturbation set.

Done when: one notebook run produces two CESM outputs and a t-test result for a precipitation perturbation, with no manual steps.

PHASE 5

Multi-site validation + hardening

~1 day

Run all three Hubs across the five sites against the reference copies, address the known Mac/Linux slowness, update the getting-started guide for the native data flow.

Done when: all three Hubs run clean on all five sites from a fresh container pull.
