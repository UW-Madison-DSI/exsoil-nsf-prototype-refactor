ExSoil Cyberinfrastructure

A containerized JupyterLab platform that brings NCAR's Community Terrestrial Systems Model together with NEON tower observations through three guided hubs — data exploration, experimental design, and experimentation.

What ExSoil is

ExSoil Cyberinfrastructure is a reproducible research environment developed at the University of Wisconsin–Madison Data Science Institute under NSF cyberinfrastructure prototype funding. It packages NCAR's cesm-lab-neon image alongside custom analytics utilities and three guided notebook hubs, so researchers can interrogate soil–ecosystem dynamics at NEON tower sites without building the CTSM toolchain themselves.

All compute happens in a per-user container with persistent storage; authentication is handled by JupyterHub with admin-approved password signup. The same image can also be pulled and run locally for offline use.

The three hubs

A typical CTSM-vs-NEON workflow is organized across three connected JupyterLab notebooks. They share a common analytics_modules Python package, so state and helpers flow naturally from one stage to the next — but each hub is self-contained, and you can enter the workflow at whichever step matches your goal.

01

Explore

Data Hub

The starting point. Browse NEON tower observations and CTSM history files side-by-side: pull half-hourly meteorological and flux measurements, visualize the five core sites (ABBY, CLBJ, CPER, KONZ, TALL) on a map, and inspect soil-moisture and energy-flux time series through an S3-backed pipeline.

02

Design

Design Hub

Set up controlled experiments. Pick a site and year, choose a perturbation — precipitation scaling, seasonal forcing, Gaussian noise, or shifts in plant-functional-type cover — and stage matched control and treatment runs ready for submission.

03

Run & evaluate

Experimentation Hub

Run the experiments and quantify their impact. Includes Kalman-filter calibration of model output against tower observations, residual misfit diagnostics, and a side-by-side comparison view for control vs. perturbed runs across key ecosystem variables.

How to access

If you're a user: click Launch the Tool above, sign up with a username and password, and an administrator will approve your account. Once approved you'll get your own JupyterLab session inside a fresh CTSM container with persistent storage.

If you'd rather run it locally with Docker:

docker run --rm -p 8888:8888 ghcr.io/uw-madison-dsi/exsoil-nsf-prototype-refactor:latest

Then open http://127.0.0.1:8888/lab in your browser. The base image is ~2 GB; the first pull takes a few minutes.

Tech stack

CTSM 5.1 JupyterLab JupyterHub xarray Docker GHCR GitHub Actions CI Caddy / Let's Encrypt

Source code, Dockerfile, and CI configuration live in the public repository. Container images are published to ghcr.io/uw-madison-dsi/exsoil-nsf-prototype-refactor on every push to main.

For administrators

To run a self-hosted JupyterHub instance using this image (the same configuration that powers the Launch button above):

git clone https://github.com/UW-Madison-DSI/exsoil-nsf-prototype-refactor.git
cd exsoil-nsf-prototype-refactor/deploy/jupyterhub
cp .env.example .env
# edit JUPYTERHUB_ADMIN_USERS in .env
docker compose up -d --build

Full deployment walkthrough including HTTPS via Caddy and Let's Encrypt: deploy/jupyterhub/README.md.
